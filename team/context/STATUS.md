## 3. Known weaknesses (accepted for now, ranked by how much they hurt)

1. **Scorer robustness.** A caller on a cropped laptop webcam scores only 10 to 15 points above random noise against their
   own key (noise ≈ 41; thresholds were loosened to 20° half-marks, 18/32° verdicts). The game layer carries the
   experience; do not promise accuracy in posts. Fix path: start-offset search, beat-clock timing, camera-tilt
   normalisation, self-consistency benchmark (`TODO.md` §3).
2. **No real FaceTime call yet.** Everything above the Chert row was verified through Chrome. The portrait canvas, the
   QR on an iPhone, Gemini's live tool calls and the Krisp path are all untested on the line.
3. **Windows.** Chert lists Windows as unsupported (our shim gets the CLI to a held line); the LiveKit native library can
   panic when a room is deleted mid-connect (hence `dance_loop.ps1`); memory pressure has killed background services;
   never run `chert doctor --agent` while `chert dev` is up. A Mac for the line is the plan, the shim the fallback.
4. **`DANCE_CALL_HANDLE` is unset**, so the scorecard has no QR, which is the share mechanic. Zero code to fix.
5. Squad colour tags can still swap when dancers cross fast; more than four people are told to cheer.
6. The backend has no auth; identity is the first name a caller says. Fine for a local demo, not for the open internet.
   Once deployed, `GET /join` can open rooms (and spend Gemini minutes) for anyone who has the link: set `JOIN_KEY`.
7. AIST++ keys are research-licensed derivatives: git-ignored, rebuilt locally with `ingest_aist`, never redistributed.
8. True barge-in while Brodie talks is not there (the echo guard drops the caller's audio; only the music has a window).
9. Gemini quirks seen on build day: stray quote characters as a line, narration (now suppressed by the persona's hard
   rule), claims of progress ("camera's locked in"), logged as `false_progress`.
