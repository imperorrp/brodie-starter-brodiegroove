## 3. Known weaknesses (accepted for now, ranked by how much they hurt)

1. **Scorer robustness.** A caller on a cropped laptop webcam scores only 10 to 15 points above random noise against their
   own key (noise ≈ 41; thresholds were loosened to 20° half-marks, 18/32° verdicts). The game layer carries the
   experience; do not promise accuracy in posts. Fix path: start-offset search, beat-clock timing, camera-tilt
   normalisation, self-consistency benchmark (`TODO.md` §3).
2. **Real-call-only code has no automated gate.** On 2026-10-12 a silent Brodie (Gemini never started) and a frozen worker
   (MediaPipe deadlock on the lite swap) had both shipped while all unit tests and the 46 eval scenarios passed: the simulator
   uses a fake voice and never swaps models. Run `chrome_test.py` (headless, real LiveKit + Gemini) before any demo or post,
   and look for `speech_dropped` rows in `data/tmp/sessions/*.jsonl`.
3. **No real FaceTime call yet.** Everything above the Chert row was verified through Chrome. The portrait canvas, the
   QR on an iPhone, Gemini's live tool calls and the Krisp path are all untested on the line.
4. **Windows.** Chert lists Windows as unsupported (our shim gets the CLI to a held line); the LiveKit native library can
   panic when a room is deleted mid-connect (hence `dance_loop.ps1`); memory pressure has killed background services (on
   2026-10-12 it killed the worker after a call, with 0.5 GB of 15.7 GB free: close spare Chrome tabs and IDEs before a call);
   never run `chert doctor --agent` while `chert dev` is up. A Mac for the line is the plan, the shim the fallback.
5. **`DANCE_CALL_HANDLE` and `DANCE_PUBLIC_URL` are unset on this laptop**, so the scorecard has no QR, which is the share
   mechanic. On Railway `DANCE_PUBLIC_URL` comes from its domain (QR → `/r/<code>`); set the handle there too so the result
   page has a Call Brodie button. Nothing ever leaves the call by itself (no iMessage/SMS in the starter): the card travels as
   the caller's screenshot, the QR and the spoken code.
6. Squad colour tags can still swap when dancers cross fast; more than four people are told to cheer.
7. The backend has no auth; identity is the first name a caller says. Fine for a local demo, not for the open internet.
   Once deployed, `GET /join` can open rooms (and spend Gemini minutes) for anyone who has the link: set `JOIN_KEY`.
   If `DATABASE_URL` (Supabase) ever goes into `.env.local`, the laptop's in-process backend (`BACKEND_URL=fake`: `chrome.ps1`,
   `dance_loop.ps1`, the simulator) writes to that database too; eval and the tests always pin SQLite.
8. AIST++ keys are research-licensed derivatives: git-ignored, rebuilt locally with `ingest_aist`, never redistributed.
9. True barge-in while Brodie talks is not there (the echo guard drops the caller's audio; only the music has a window).
10. Gemini quirks seen on build day: stray quote characters as a line, narration (now suppressed by the persona's hard
   rule), claims of progress ("camera's locked in"), logged as `false_progress`.
